# アーキテクチャ設計

## 全体像

```
                     ユーザー
                        │  相談内容 / フィードバック・指示
                        ▼
                 ┌───────────────┐
                 │  AI秘書(Coordinator) │  ← 全体像を把握し、司会・要約・提案を担当
                 └───────────────┘
                        │  論点を専門家パネルに提示
                        ▼
        ┌──────────┬──────────┬──────────┬──────────┐
        │ 専門家A   │ 専門家B   │ 専門家C   │   ...    │
        └──────────┴──────────┴──────────┴──────────┘
                        │  各専門家の初回意見
                        ▼
                 討議ラウンド（お互いの意見を踏まえて再意見）
                        │
                        ▼
                 AI秘書が統合し、提案としてユーザーに提示
                        │
                        ▼
            ユーザーが承認 / 修正指示 → 1へ戻る（ループ）
```

## 役割

### AI秘書（Coordinator）

- 会議全体の進行役。個々の専門家の詳細な専門知識には立ち入らず、
  「全体像の把握」「論点の整理」「専門家間の矛盾の指摘」「最終提案の作成」
  に専念する。
- ユーザーとの唯一の窓口。専門家の生の発言をそのまま流すのではなく、
  意思決定に必要な形に要約・翻訳する。
- ユーザーの指示を専門家パネルへの「次の論点」として再展開する。

### 専門家AI（Expert）

- `experts/experts.yaml` で定義された人格（役職・専門分野・口調・
  判断基準）を持つ、単一領域に特化したAI。
- 与えられた案件に対して自分の専門領域からの意見を述べる。
- 討議ラウンドでは、他の専門家の初回意見を読んだ上で、賛成/懸念/
  追加の論点を述べる（＝会議での発言に相当）。

## 会議（パネル討議）のフロー

1. **論点提示**: AI秘書がユーザーの相談内容をそのまま、あるいは論点を
   整理した形で専門家全員に提示する。
2. **初回意見（並行）**: 各専門家が独立に一次意見を返す。専門家同士は
   まだお互いの意見を見ない。
3. **討議ラウンド**: 各専門家に「他の専門家全員の初回意見」を見せた上で、
   自分の立場からのコメント（賛同・反論・補足）を求める。これを
   `PanelMeeting` は1ラウンドのみ実装しているが、`rounds` 引数で
   複数ラウンドに拡張可能。
4. **統合提案**: AI秘書が初回意見＋討議内容をすべて受け取り、
   - 専門家の見解が一致している点
   - 意見が割れている点とその論点
   - 秘書としての推奨方針
   をまとめてユーザー向けの提案として出力する。
5. **ユーザー判断**: ユーザーが承認するか、追加の指示・質問を入力する。
   追加指示があれば、それを新たな論点として2へ戻る。

## 拡張ポイント

- **専門家の追加/差し替え**: `experts/experts.yaml` にエントリを足すだけ。
  コード変更は不要。
- **討議ラウンド数**: `PanelMeeting(rounds=2)` のように増やせる。
- **専門家の一部のみ招集**: 案件の内容に応じてAI秘書が関連する専門家を
  選別するロジックは `Coordinator.select_relevant_experts` に用意している
  (現状は全員招集がデフォルト。将来的にLLMによる選別に差し替え可能)。
- **永続化**: 現状は1セッション内のメモリ上でのみ議事録を保持する。
  複数案件・複数日にまたがる相談を扱う場合は、議事録の保存先
  （ファイル/DB）を追加する。

## 技術選定

- 言語: Python 3.11+
- LLM: Anthropic Claude API（`anthropic` SDK）
- 各専門家・秘書はそれぞれ独立したシステムプロンプトを持つだけの
  軽量な構成とし、特定のマルチエージェントフレームワークには依存しない
  （将来的にClaude Agent SDK等への移行がしやすいよう、疎結合にしている）。
