# tsunagusouzoku（つなぐ相続）— AI専門家パネル

複数の専門家AIが「会議」を行い、最善の方針を議論・策定し、リーダー役の
AI秘書がそれを整理してユーザーに提案する仕組みのプロトタイプです。

## 目指す仕組み（ユーザーの構想）

1. 各分野の専門家をAIとして個別に作る
2. 専門家AI同士が会議を行い、議論する
3. 議論の結果、最善の方法を考え、具体案として構築する
4. 専門家たちのトップに立つ「AI秘書」が全体像を把握し、まとまった提案として
   ユーザーに提示する
5. ユーザーが提案を判断し、追加の指示を出す
6. その指示を受けて専門家会議が再度行われる（1〜5を繰り返す）

## このリポジトリでの前提

リポジトリ名から「相続（そうぞく）」関連のコンサルティング業務を支援する
仕組みだと推測し、専門家の初期セットを相続分野（税理士・弁護士・司法書士・
不動産鑑定士・ファイナンシャルプランナー）で用意しました。ただし専門家の
種類は `experts/experts.yaml` を書き換えるだけで自由に差し替えられる、
汎用的な構成にしています。想定領域が異なる場合は、この設定ファイルを
書き換えてください。

## 構成

```
experts/experts.yaml   専門家AIの人格定義（役職・専門・システムプロンプト）
src/expert.py          専門家AI 1体を表すクラス
src/coordinator.py      AI秘書（リーダー）。会議を進行し、提案をまとめる
src/panel.py            会議のオーケストレーション（初回意見→討議→統合提案）
src/cli.py              対話式CLIエントリポイント
```

## セットアップ

```bash
pip install -r requirements.txt
cp .env.example .env   # ANTHROPIC_API_KEY を設定
```

## 使い方

```bash
python -m src.cli
```

案件・相談内容を入力すると、以下の流れで進行します。

1. 各専門家AIが初回意見を出す（並行）
2. 専門家AI同士が互いの意見を踏まえて討議する
3. AI秘書が討議内容を統合し、ベストな方針をユーザーに提案する
4. ユーザーがフィードバック・追加指示を入力すると、その指示を踏まえて
   専門家会議が再度行われる

詳しい設計思想は [docs/architecture.md](docs/architecture.md) を参照してください。
